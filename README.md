# Daily Gambit ♟

A playful daily chess trainer for young players. Each day of the week has a short lesson you do right in the app, on a Lichess-style board with Stockfish:

| Day | Lesson | Time |
|---|---|---|
| Monday | **Woodpecker tactics** — a fixed set of 200 puzzles, repeated in rounds that get faster | 30 min |
| Tuesday | **Theoretical endgames** vs Stockfish — key squares, opposition, triangulation, Lucena, Philidor, Vančura | 30 min |
| Wednesday | **Guess the move** — replay a Capablanca or Rubinstein win and guess every move | 30 min |
| Thursday | **Woodpecker speed run** (Monday's puzzles, 1.5× faster) + coordinates quiz | 30 min |
| Friday | **Blindfold tactics** (read aloud) + **threat drills** | 30 min |
| Weekend | **Serious game** vs Stockfish with a clock and "sit on your hands" confirmations, then an engine-free notebook; Stockfish unlocks only after the notebook is filled | 90 min |

Built-in rules: a *circuit break* stops weekday sessions when accuracy falls below 70%, and the *engine delay* rule locks Stockfish until the player has written their own analysis.

Gamified with XP, ranks (Pawn → Grandmaster), streaks, badges and real-world prizes a parent hands over after fully finished sessions. Available in **Slovak, German and English**.

## Run it

```sh
python3 build.py            # creates dist/
cd dist && python3 -m http.server 8765
# open http://localhost:8765
```

`dist/` is a plain static site, so any static host works.

> **Storage:** installed or opened from any normal web address, the app keeps all progress on the device (browser storage, marked persistent) — back it up with **Log → Backup**. Inside a claude.ai artifact it uses the artifact's database (`window.claude.use('db')`) instead. Deployment with a family-only login is described in [DEPLOY.md](DEPLOY.md).

## Install / offline

Daily Gambit is an installable Progressive Web App. After the first visit over http(s) a service worker (`sw.js`, generated by `build.py`) stores **every** file of the app — fonts, Stockfish, puzzles, games and sounds included — so it then works with no internet at all.

- **Install:** in Chrome/Edge/Android an "📲 Install app" pill appears (it can be closed with ✕); otherwise use the browser menu → *Install app* / *Add to Home Screen* (on iPhone: Share → *Add to Home Screen*).
- **Updates:** when a new version is deployed, the app keeps running the old one and shows a "New version — tap to update" pill; tapping it switches to the new version and reloads.
- **Progress** is stored on the device (in the browser's storage for this site), not on a server. Clearing site data or uninstalling removes it.

Icons are generated from the otter mascot with `python3 tools/make_icons.py`. `public/_headers` sets cache headers for Cloudflare Pages (`sw.js` and `index.html` must not be cached long). `tests/e2e_pwa.py` checks install, offline use and updates in Chrome.

## Project layout

```
src/            app source — i18n.js, core.js (data, scoring, storage, board, engine),
                lessons.js (all six lessons), openings.js (Openings tab), ui.js (screens), index.html, pieces-sprite.svg,
                pwa.js (install + update pills), sw.js (service-worker template)
public/         static files copied as-is: libraries, Stockfish, puzzle/game data, sounds, css,
                fonts, icons, manifest, Cloudflare _headers
tools/          scripts that generated the data and checked the endgame positions;
                openings_src.py is the opening repertoire and traps, build_openings.py builds and
                Stockfish-checks it (python3 tools/build_openings.py <chess-openings dir> --check)
tests/          end-to-end browser tests (Playwright + Chrome)
build.py        joins src/ + public/ into dist/ and generates dist/sw.js
```

## Privacy

This repository contains **no personal data and no secrets**: no player names, no progress, no keys or tokens. The optional Lichess token for opening statistics is kept only in the browser of the device where it was entered (not in backups, not in shared storage). Progress is stored on the device or in the app's own storage, never in the code. Please keep it that way in any contribution: no real names, photos, exported progress files or credentials.
